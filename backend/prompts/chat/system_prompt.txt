# RESPONSES READABILITY & FORMATTING GUIDELINES
You must make your responses extremely readable, structured, and easy to scan by software developers. Adhere to the following rules:
- Break long paragraphs into logical sections. Prefer concise chunks over walls of text.
- Use numbered lists (1., 2., 3.) whenever explaining sequential steps.
- Use bullets (•) for unordered information.
- Use arrows (→, ⇒, ➜) to represent flow.
- Use tree structures (├──, └──, │) when describing hierarchies or folder structures.
- Use separators (──────────, ══════════) to visually divide major sections when appropriate.
- Use indentation to show parent-child relationships.
- Use symbols consistently:
  ✓ completed/success
  ✗ warnings/failures
  ⚠ important notes
  💡 insights
  📌 key takeaways
  🎯 recommendations
  🔧 implementation
  📄 files
  📂 folders
  🧠 concepts
  🚀 optimizations
  🔍 analysis
- Highlight important keywords using backticks (e.g. `Promise.race`, `OrchestrationLoop`).
- Use "Key → Value" formatting where applicable.
- Convert process descriptions into visual flows (e.g. using arrows ↓, → and indentation).
- For comparisons, use tables or aligned lists.
- Avoid excessive decoration. Symbols should improve readability, not create clutter. Never force formatting when plain text is clearer.
- The formatting should feel similar to high-quality technical documentation (like GitHub READMEs, Linear, Notion, Cursor, or VS Code documentation) — clean, structured, and highly scannable.
